# 3DSFERA

Трёхмерная витрина, где товар показывают в действии до покупки: антенна
разворачивается, робот-пылесос едет по комнате, кресло раскладывается. Дальше —
заказ и физическая доставка. Вторая половина продукта — кабинет поставщика, где
производитель сам загружает GLB, настраивает анимации и выставляет товар в свой
павильон без участия нашей команды.

## Запуск

```bash
make dev
```

Одна команда: создаёт `.env`, ставит зависимости, скачивает ассеты мира,
собирает локацию, генерирует библиотеку материалов и демо-модели, поднимает
Postgres, MinIO и Mailpit в докере, применяет миграции, заливает демоданные и
запускает API вместе с веб-приложением.

Первый запуск заметно дольше остальных. Локация — настоящая парижская улица
(Amazon Lumberyard Bistro, CC BY 4.0): около двух гигабайт исходников качаются
и перекодируются в четыре уровня детализации с мип-цепочками, минут сорок.
Генерация 4K-материалов — ещё семь минут, обработка пяти моделей — десять.
Дальше `make dev` пропускает всё это. Бинарники не лежат в гите: сборка
детерминирована, поэтому `make location` и `make assets` всегда дают тот же
результат, а клон репозитория весит мегабайты, а не гигабайты.

| Что             | Где                   |
| --------------- | --------------------- |
| Веб-приложение  | http://localhost:5173 |
| API             | http://localhost:4000 |
| Почта (Mailpit) | http://localhost:8025 |
| MinIO console   | http://localhost:9001 |
| Prisma Studio   | `make db-studio`      |

Требования: Node 22+, pnpm 10+, Docker с плагином compose. Для `make installer`
дополнительно нужен Rust — веб-версии он не нужен.

Если `make dev` падает на `make: pnpm: No such file or directory`, значит
инструментов ещё нет. На macOS:

```bash
# Homebrew, если его нет
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
eval "$(/opt/homebrew/bin/brew shellenv)"   # Apple Silicon

brew install node pnpm
brew install --cask docker                  # и запустить Docker Desktop
```

Проверка: `node -v` даёт v22 или выше, `pnpm -v` — 10 или выше, `docker ps`
выводит список контейнеров, а не ошибку подключения к демону.

Если Node стоит через `nvm`, pnpm лучше включить через corepack — версия тогда
берётся из поля `packageManager`:

```bash
corepack enable && corepack prepare pnpm@10.33.0 --activate
```

С Homebrew-нодой этот путь не работает: corepack из формулы вырезан.

Утилиту [KTX-Software](https://github.com/KhronosGroup/KTX-Software) ставить не
нужно: `make location` скачивает её сам в `apps/tools/.ktx`. Для загрузок
поставщиков она берётся из PATH, если есть; если нет, текстуры переводятся в
WebP, а в отчёте оптимизации честно пишется, что шаг пропущен.

## Команды

```bash
make help        # список целей
make up          # только инфраструктура
make app         # только приложение (api + web)
make db-dev      # создать миграцию из изменений схемы
make db-reset    # снести базу, накатить миграции, засеять заново
make seed        # демоданные
make test        # юнит-тесты (Vitest)
make e2e         # сквозные тесты (Playwright)
make lint        # ESLint
make typecheck   # tsc --noEmit по всем пакетам
make world-assets # скачать ассеты мира (HDRI, сканы материалов, шрифт)
make location    # скачать и собрать локацию (~40 минут, один раз)
make desktop     # Tauri-оболочка поверх дев-сервера (нужен Rust)
make installer   # установщик под текущую платформу (нужен Rust)
make textures    # сгенерировать библиотеку 4K PBR-материалов (~6 минут)
make assets      # перегенерировать материалы и демо-модели
```

## Структура

```
apps/
  api/        Fastify + Prisma. Бизнес-логика в src/modules/*/service.ts,
              HTTP — только транспорт
  web/        Vite + React + R3F. Логика в src/features/*, компоненты тонкие
  desktop/    Tauri-оболочка над той же веб-сборкой, своего 3D-кода нет
  tools/      генератор демо-моделей: GLB с настоящими анимационными клипами
packages/
  shared/     zod-схемы, DTO, словари ru/en, контракт ошибок —
              один источник правды для фронта и бэка
docker/       инициализация MinIO
docs/         архитектура и руководство поставщика
```

## Состояние по этапам

- [x] **6. Десктоп** — Tauri-оболочка над той же веб-сборкой, установщики для
      macOS (Apple Silicon и Intel) и Windows собираются матрицей в GitHub
      Actions, иконка генерируется из кода, CSP пропускает воркеры декодеров и
      не пускает никуда наружу
- [x] **5. Админка** — очередь модерации с 3D-предпросмотром и измерениями
      модели, одобрение и отклонение с обязательной причиной и письмом
      поставщику, реестр компаний с блокировкой, слоты павильонов с отказом при
      занятом слоте, журнал действий с постраничной выборкой по ключу, метрики
      с оборотом и конверсией
- [x] **4. Покупка и доставка** — корзина, оформление заказа с расчётом
      доставки по весу и стране, оплата за интерфейсом `PaymentProvider`
      (встроенный тестовый провайдер и Stripe в тестовом режиме),
      статус заказа с трек-номером, входящие заказы у поставщика и смена
      статуса отгрузки, письма покупателю на его языке
- [x] **3. Трёхмерный мир** — настоящая улица (Amazon Lumberyard Bistro,
      CC BY 4.0) в четырёх уровнях детализации, карта проходимости строится из
      геометрии, витрины поставщиков находятся по вывескам самой сцены, ходьба
      на WASD и джойстике, товарные стенды с LOD и ленивой подгрузкой,
      «показать в действии», покупка из сцены, четыре уровня качества с
      автоподбором и фоллбэк на плоский каталог
- [x] **2. Кабинет поставщика** — мастер загрузки из шести шагов, проверка GLB
      в браузере и на сервере по содержимому, пайплайн оптимизации
      (Draco, LOD, текстуры), 3D-вьювер в кабинете, настройка анимаций,
      импорт из CSV, статусы модерации, статистика
- [x] **1. Каркас** — монорепо, docker-compose, Prisma-схема и миграции,
      регистрация и вход, три роли, защищённые маршруты, i18n ru/en
