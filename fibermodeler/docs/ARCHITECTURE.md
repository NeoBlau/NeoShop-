# FiberModeler — архитектура

Документ описывает, как устроено приложение и почему приняты именно такие решения.

## 1. Обзор

FiberModeler — фронтенд-приложение без бэкенда и без зависимостей. Всё выполняется в браузере:
модель живёт в памяти, хранится в IndexedDB и выгружается в файл `.fibermodel`.

Почему браузер, а не Qt/PySide6: приложение должно одинаково работать на macOS, Windows и Linux
без установки, компиляции и подписи; SVG-рендеринг даёт векторный экспорт «бесплатно»; результат
можно открыть одним файлом. Модульность и строгое разделение слоёв при этом сохранены —
код организован так же, как организовали бы десктопное приложение.

```
              ┌─────────────────────────────────────────────┐
              │                   ui/                       │  меню, панели, диалоги, палитра команд
              ├─────────────────────────────────────────────┤
   canvas/ ◄──┤   app.js  (контроллер: все команды)          ├──► io/     экспорт, импорт, файлы
              ├─────────────────────────────────────────────┤
              │  core/ (модель, история, выделение, буфер)   │◄── layout/  авторазметка, выравнивание
              ├─────────────────────────────────────────────┤
              │  notations/ (BPMN 2.0, IDEF0: типы, правила, │
              │             отрисовка, валидация, шаблоны)   │◄── ai/      генерация моделей
              └─────────────────────────────────────────────┘
```

Правило зависимостей: `notations` ничего не знает о DOM, `core` ничего не знает о нотациях,
`ui` знает обо всех, но никто не знает об `ui`. Поэтому 69 модулей импортируются без единого цикла,
а всё, кроме слоя `ui`, тестируется в Node.

## 3. Модель данных

Проект — обычный JSON. Никаких классов внутри данных: их можно клонировать, сериализовать,
сравнивать и хранить без адаптеров.

```jsonc
Project {
  schema, id, name,
  meta: { author, company, description, version, created, modified },
  documentation,
  diagrams: [ Diagram ]
}

Diagram {
  id, notation: "bpmn" | "idef0", name,
  nodes: [ Node ], edges: [ Edge ],
  parentDiagramId, parentNodeId,        // декомпозиция
  meta: { author, description, version, documentation, ... },
  view: { x, y, zoom, saved }
}

Node { id, type, x, y, w, h, label, parent, props: {}, style: {} }
Edge { id, type, source, target, sourceSide, targetSide, waypoints: [], routing, label, props, style }
```

`Doc` (core/model.js) добавляет поверх этих данных индексы (`id → элемент`), инварианты
(удаление узла отвязывает детей) и события изменений. Иерархия декомпозиции хранится ссылками
`parentDiagramId` / `parentNodeId`, поэтому дерево строится по данным, а не дублируется.

## 4. Нотации как данные

Каждый элемент описан дескриптором:

```js
{
  id: 'userTask', category: 'activity', group: 'activities',
  name: { en: 'User task', ru: 'Пользовательская задача' },
  defaultSize, minSize, paletteSize, resizable, container, decomposable, labelPlacement,
  draw(node, ctx) -> SVG-разметка в локальных координатах,
  props: [ { key, type, label, group, options } ],
  bpmn: { element: 'userTask', eventDefinition: null }   // отображение в BPMN 2.0 XML
}
```

Из одного дескриптора берут данные палитра, холст, панель свойств, меню «изменить тип»,
валидатор и XML-сериализатор. Добавление элемента — одна запись в каталоге; добавление нотации —
один модуль в `notations/index.js`.

`draw` возвращает строку SVG, а не DOM: её одинаково использует экран, экспорт SVG и (через
парсер) экспорт PDF, поэтому «что на экране — то и в файле» выполняется по построению.

Правила соединений тоже данные нотации: `canConnect(diagram, source, target, type)` возвращает
`{ok, type, reason}`; интерактив рисует запрет ещё до отпускания кнопки мыши.

### IDEF0

Семантика IDEF0 задаётся геометрией: сторона блока определяет роль стрелки
(лево — Input, верх — Control, право — Output, низ — Mechanism/Call). Роль хранится в типе связи,
стороны — в `sourceSide`/`targetSide`; смена роли в свойствах меняет и сторону подключения.
Граничные стрелки — узлы `idef0Anchor` с ICOM-кодом; при создании декомпозиции стрелки
родительского блока переносятся в дочернюю диаграмму как граничные — это то, ради чего IDEF0
и существует.

## 5. Холст

* **SVG-сцена** с четырьмя слоями: контейнеры (пулы, дорожки) → связи → узлы → оверлей.
* **Viewport** — одна матрица `translate(tx,ty) scale(zoom)` на группе; панорама и зум не трогают
  узлы. Сетка — SVG-паттерн с тем же трансформом.
* **Оверлей** (выделение, ручки, направляющие, превью связи, рамка выбора) рисуется в экранных
  координатах в нетрансформируемом слое: ручки не «толстеют» при зуме и не требуют пересчёта узлов.
* **Инкрементальный рендер**: `refreshNode(id)` меняет `transform` и `innerHTML` одного `<g>`;
  при перетаскивании пересчитываются только связи, инцидентные перемещаемым узлам.
* **Роутинг** (`canvas/routing.js`) считает геометрию всех связей одной функцией: сначала
  распределяет якоря по сторонам (чтобы параллельные потоки не сливались), затем строит
  ортогональный маршрут с минимумом изломов, обходя блоки при «обратных» связях.

Замер на 600 узлах / 580 связях (headless Chromium): первый рендер 114 мс, пересчёт маршрутов 2 мс,
кадр зума ~13 мс, кадр перетаскивания ~14 мс, экспорт SVG 6 мс.

## 6. Undo/Redo

`History` — стек команд с интерфейсом `do/undo`. Базовая реализация — memento: `history.run(label, ids, fn)`
снимает снимок затронутых диаграмм до и после мутации и кладёт в стек `SnapshotCommand`.

Почему снимки: они дают корректную отмену для любой операции, включая массовые (импорт,
авторазметка, генерация, удаление узла вместе со связями и дочерними диаграммами), без написания
обратной операции для каждой функции. Стек ограничен по количеству и по оценке объёма.

Интерактивные жесты (перетаскивание, resize) мутируют модель напрямую ради 60 fps, а в конце
жеста вызывают `commitLive(token)` — получается ровно один шаг отмены. Если мутация бросила
исключение, `run` откатывает состояние: модель не остаётся «полуприменённой».

## 7. Импорт и экспорт

| Формат | Модуль | Особенности |
|---|---|---|
| `.fibermodel` | `io/projectfile.js` + `io/zip.js` | ZIP (собственная реализация, deflate через `CompressionStream`), читаемая структура |
| BPMN 2.0 XML | `io/bpmn.js` | коллаборации, пулы, дорожки, `laneSet`, условия, документация, BPMN-DI с координатами и точками маршрутов |
| SVG | `io/svgexport.js` | CSS-переменные подставляются значениями — файл самодостаточен |
| PNG / JPEG | `io/raster.js` | SVG → `<img>` → canvas, масштаб настраивается |
| PDF | `io/pdf.js` | собственный писатель: SVG разбирается и переводится в операторы PDF |
| JSON | `io/projectfile.js` | модель как есть |

**PDF** — векторный: прямоугольники, окружности, пути (включая дуги `A`), полигоны, трансформации,
прозрачность, пунктиры. Текст остаётся текстом: в документ встраивается подмножество DejaVu Sans
(CIDFontType2, Identity-H, `ToUnicode`), поэтому кириллица выделяется и ищется в любом просмотрщике.
Шрифт готовится скриптом `tools/subset_font.py` (112 КБ вместо 757 КБ) и подключается динамическим
импортом — при обычной работе он не загружается.

XML разбирается собственным парсером (`io/xml.js`), а не `DOMParser`: импорт одинаково работает
в браузере и в тестах Node.

## 8. Авторазметка

* **BPMN** — послойный алгоритм в духе Сугиямы: устойчивое к циклам разбиение на слои (самый
  длинный путь), уменьшение пересечений барицентрами, координаты медианным проходом с
  восстановлением зазоров; дорожки задают вертикальные полосы, объекты данных и примечания
  ставятся рядом с владельцем и не вылезают из дорожки.
* **IDEF0** — «лестница»: блоки по диагонали в топологическом порядке, граничные стрелки
  прижимаются к рамке по своей роли.

`layout/align.js` — выравнивание, распределение, выравнивание размеров; всё возвращает список
изменений `{id, x, y, w, h}`, который применяется одной командой истории.

## 9. Генерация моделей

Спецификация модели (`ai/schema.js`) — общий язык для шаблонов, табличного конструктора и любых
генераторов: узлы, связи, дорожки — или контекст и функции с ICOM для IDEF0. `buildDiagrams(spec)`
превращает её в настоящие диаграммы: раздаёт идентификаторы, создаёт дорожки, связывает выходы
одной функции со входами другой, применяет авторазметку.

* `ai/local.js` — **офлайн-движок**: это не языковая модель, а детерминированный разбор текста
  (разбиение на шаги, определение типа по глаголам и ролям, раскрытие «если … то …» в шлюз с
  ветками, выделение ICOM-фраз по маркерам) плюс подбор ближайшего шаблона, если на входе только
  заголовок.
* `ai/providers.js` — Claude, OpenAI, Ollama, произвольный endpoint. Ключи хранятся локально.
* `ai/index.js` — если внешний вызов не удался, модель строится офлайн-движком: приложение
  никогда не остаётся без результата.

Ответ внешней модели проходит `normalizeSpec` — неизвестные типы, висящие связи и мусор
отбрасываются до попадания на холст.

## 10. Интерфейс

* **Единый реестр команд** (`ui/commands.js`): меню, тулбар, палитра `⌘K` и горячие клавиши
  читают один список — команда не может существовать в одном месте и отсутствовать в другом.
* **Панели** (`ui/panels/`) подписаны на события модели и выделения и перерисовывают только себя.
* **Свойства** генерируются из дескрипторов типов, поэтому новый элемент сразу получает
  корректную форму редактирования.
* **Диалоги** — общий примитив `openDialog` с обработкой Escape, фокуса и подложки.
* **i18n** — плоские словари `ru`/`en` для интерфейса и двуязычные имена в дескрипторах типов;
  тест проверяет, что словари не разошлись.
* **Темы** — CSS-переменные, включая палитру элементов диаграмм, поэтому тёмная тема меняет и схему.

## 11. Хранение

IndexedDB — проекты и точка восстановления, localStorage — настройки и список недавних.
Автосохранение раз в N секунд и при закрытии вкладки; при старте предлагается восстановленный проект.
Файл `.fibermodel` остаётся основным способом переноса и резервного копирования.

## 12. Тесты

`tests/run.js` — свой раннер (зависимостей нет). Покрыты: модель и история (включая откат
при ошибке), выделение и буфер, геометрия, каталоги типов и отрисовка каждого типа, правила
соединений, валидаторы обеих нотаций, роутинг, авторазметка (в том числе «никаких пересечений»
и устойчивость к циклам), ZIP, XML, BPMN round-trip, файл проекта, SVG и PDF, генерация из текста,
шаблоны, табличный конструктор, демо-проект, синхронность словарей.

Интерфейс проверяется в headless-браузере (Playwright): запуск, палитра, установка элемента,
инлайн-ввод, связь быстрым хендлом, undo/redo, валидация, авторазметка, палитра команд, все
экспорты, печать, тёмная тема и сборка одним файлом.
