# Архитектура 3DSFERA

Документ описывает принятые решения и причины, по которым они приняты. Он
обновляется в конце каждого этапа.

## Общая картина

```
                 ┌───────────────────────────────┐
   браузер /     │  apps/web                     │
   Tauri-окно ──▶│  React 19 + R3F (этап 3)      │
                 │  Zustand, Tailwind, i18next   │
                 └───────────────┬───────────────┘
                                 │ fetch, credentials: include
                                 │ httpOnly-кука sfera_sid
                 ┌───────────────▼───────────────┐
                 │  apps/api                     │
                 │  Fastify 5, zod, argon2       │
                 │  modules/*/service.ts —       │
                 │  бизнес-логика без HTTP       │
                 └───┬──────────────────┬────────┘
                     │ Prisma 7         │ S3 SDK
             ┌───────▼──────┐   ┌───────▼────────┐
             │ PostgreSQL   │   │ MinIO / S3     │
             │ 16           │   │ GLB, KTX2,     │
             │              │   │ превью         │
             └──────────────┘   └────────────────┘
```

`packages/shared` лежит поперёк: zod-схемы, DTO, коды ошибок и словари ru/en
собираются один раз и используются обеими сторонами. Схема, по которой сервер
валидирует запрос, — ровно тот же объект, которым форма подсвечивает поля.

## Решения и причины

### Монорепо на pnpm-воркспейсах, без Turborepo

Три приложения и один общий пакет. Turborepo окупается на десятках пакетов, а
здесь добавил бы ещё один конфиг и ещё один кэш. `pnpm --filter` покрывает всё,
что нужно.

### Бизнес-логика отдельно от транспорта

`src/modules/auth/service.ts` принимает хэндл базы и обычные значения, возвращает
обычные значения и бросает `AppError`. Он ничего не знает про Fastify, куки и
статус-коды — поэтому его тесты не поднимают сервер. Роут переводит результат в
HTTP. То же на фронте: `src/features/*/model.ts` — чистые функции, компоненты
только рендерят.

### Сессии в базе, а не JWT

Кука несёт случайный токен на 256 бит, в базе лежит его SHA-256. Из этого следуют
два свойства, которых у JWT нет без дополнительной инфраструктуры: сессию можно
отозвать мгновенно (блокировка поставщика выкидывает его из всех вкладок), а
дамп таблицы `sessions` нельзя переиграть как логин. Цена — один запрос к базе на
проверку; он идёт по уникальному индексу и стоит меньше, чем проверка подписи с
обращением к списку отзыва.

`lastSeenAt` обновляется не чаще раза в час — иначе каждый GET превращался бы в
запись.

### Пароли: argon2id

19 МиБ памяти, два прохода, параллелизм 1 — середина рекомендации OWASP. Логин
несуществующего пользователя всё равно прогоняет хэширование, чтобы отсутствие
аккаунта нельзя было определить по времени ответа.

### Защита от CSRF: SameSite=Lax плюс проверка Origin

Кука `sfera_sid` — `httpOnly`, `SameSite=Lax`, `Secure` в проде. Lax уже
отсекает межсайтовые POST-формы. Хук в `plugins/security.ts` дополнительно
отклоняет мутирующие запросы с чужим `Origin`. Запросы вообще без `Origin`
(curl, сервер-сервер) проходят: браузер без этого заголовка кук не пришлёт.

### Контракт ошибок: код, а не предложение

API отдаёт `{ error: { code: 'ERR_EMAIL_TAKEN', message, params?, issues? } }`.
`message` — английская строка для логов и curl, пользователю она не показывается
никогда. Текст собирает клиент из своего словаря. Без этого язык интерфейса и
язык писем разъезжаются в первый же месяц.

`issues` адресуют поле точечным путём (`address.postalCode`), форма подсвечивает
именно его.

### i18n с первого этапа

Словари живут в `packages/shared/src/i18n`. Тип словаря выводится из русского
файла, английский типизирован против него: забытый ключ — ошибка компиляции, а
не сырой ключ в интерфейсе. Тест `dictionaries` дополнительно сверяет наборы
ключей. Язык гостя берётся из localStorage, затем из браузера; у залогиненного
пользователя он хранится в аккаунте и переезжает между устройствами.

### Деньги и размеры — целые числа

Цены в минорных единицах (копейки), вес в граммах, габариты в миллиметрах. Float
для денег не используется нигде, включая расчёт доставки.

### Персональные данные

`ShippingAddress` — отдельная таблица, связанная с заказом один к одному. Ни имя,
ни телефон, ни адрес не денормализуются в `Order`, поэтому ограничение доступа
делается в одном месте. В `AuditLog` не пишутся ни адреса, ни email: только id
сущностей, действие и хэш IP с секретом (`hashIp`), который нельзя обратить
радужной таблицей.

### Prisma 7 и драйверные адаптеры

В седьмой версии строка подключения ушла из `schema.prisma`: миграции читают её
из `prisma.config.ts`, клиент получает через `@prisma/adapter-pg`. Клиент
генерируется в `apps/api/src/generated/prisma` и в гит не коммитится —
`postinstall` вызывает `prisma generate`.

### Файлы пользователей

Всё, что загрузил поставщик, лежит в S3-совместимом хранилище. Публичный префикс
`public/` (оптимизированные GLB, превью) отдаётся анонимно, оригиналы —
только по presigned-ссылкам с коротким сроком. Проверка формата — по содержимому
файла (magic bytes `glTF`), не по расширению; это будет реализовано на втором
этапе вместе с загрузкой.

В проде статику пользователей нужно отдавать с отдельного домена с жёсткими
`Content-Type` и `Content-Disposition` — иначе загруженный HTML исполнится в
контексте приложения.

## Загрузка и оптимизация моделей (этап 2)

### Проверка по содержимому, а не по имени

`packages/shared/src/glb.ts` разбирает контейнер GLB и документ glTF: считает
треугольники, материалы, текстуры, читает имена и длительности анимационных
клипов. Одна и та же функция вызывается дважды:

- в браузере — до отправки, чтобы поставщик узнал о проблеме за секунду, а не
  после сорока мегабайт;
- на сервере — по полученным байтам, потому что клиентская проверка это
  удобство, а не граница безопасности.

Расширение не используется нигде. PNG, переименованный в `chair.glb`,
отклоняется по магическому числу: в файле должно быть `glTF` или валидный
JSON с блоком `asset`.

### Пайплайн

`apps/api/src/modules/products/pipeline.ts`, порядок шагов не случаен:

1. `dedup` и `prune` — выкинуть дубликаты и неиспользуемое, чтобы дальше
   работать с меньшим объёмом;
2. `weld` — сварить вершины: без общих вершин упрощение не сможет схлопнуть
   ни одного ребра;
3. текстуры — сжатие через sharp в WebP с потолком 2048 px; KTX2 требует
   внешней утилиты `ktx`, и если её нет, шаг отмечается пропущенным в
   `stats.skipped`, а не выдаётся за выполненный;
4. Draco — сжатие геометрии, даёт основной выигрыш (40–60% на демо-моделях);
5. LOD — два уровня, 50% и 25% от исходной геометрии, с растущим допуском
   ошибки. Уровень, который не убирает хотя бы 10% треугольников, не
   сохраняется вовсе: на hard-surface моделях упрощать нечего, а лишний файл
   стоит сцене загрузки и переключения.

Каждый уровень считается от оригинала, а не от предыдущего: иначе ошибка
упрощения складывалась бы сама с собой.

### Очередь

Загрузка возвращает `202` сразу после того, как оригинал сохранён и job создан;
мастер опрашивает `/api/supplier/products/:id/job`. Держать HTTP-соединение
минуту ради сорокамегабайтной модели незачем.

Задачи выполняются строго по одной: оптимизация упирается в процессор и держит
модель в памяти целиком, две параллельных удвоили бы пик потребления.
При старте сервер подбирает задачи, оставшиеся в `PENDING` или `RUNNING` после
перезапуска, — иначе модель навсегда осталась бы «в обработке».

### Раскладка в хранилище

```
private/products/<id>/original-<ts>.glb    оригинал, только presigned-ссылки
public/products/<id>/model-<ts>.glb        оптимизированная модель, LOD 0
public/products/<id>/model-lod1-<ts>.glb   LOD 1
public/products/<id>/model-lod2-<ts>.glb   LOD 2
public/products/<id>/preview-<ts>.webp     кадр из вьювера
```

Всё пользовательское отдаётся с `Content-Disposition: attachment` и явным
`Content-Type`. Превью не принимается «как есть»: PNG проверяется по сигнатуре
и переупаковывается через sharp — это снимает метаданные и отсекает файл,
который лишь притворяется картинкой.

### Никаких внешних CDN в 3D

Две библиотечных умолчания пришлось отключить осознанно:

- `useGLTF` из drei тянет декодер Draco с `gstatic.com`;
- `<Environment preset=...>` скачивает HDRI из публичного бакета.

Оба варианта означают, что сцена не работает без интернета и блокируется CSP
десктопной оболочки. Декодеры Draco и Basis копируются из установленного
пакета `three` в `public/` скриптом `apps/web/scripts/copy-decoders.mjs`
(версия всегда совпадает с lock-файлом), а освещение собрано в сцене из
`Lightformer`. Если на третьем этапе понадобится настоящий HDRI, он будет
лежать у нас, а не на чужом домене.

### Состояние мастера

Шаги описаны в `apps/web/src/features/products/wizard.ts` чистыми функциями:
`evaluateStep` отвечает, можно ли уйти со шага, и почему нельзя. Поэтому
правило «модель с клипами, но без кнопок дальше не пускаем» проверяется
юнит-тестом, а не кликами в браузере.

## Трёхмерный мир (этап 3)

### Локация: почему не готовый ассет из UE5

Вопрос стоял так: взять город или ТЦ из магазина Unreal или собрать самим.
Взять не получится по двум независимым причинам.

Первая — лицензия. Контент Fab и Unreal Marketplace в большинстве случаев
лицензирован для использования внутри Unreal Engine. Витрина на WebGL — не
Unreal, и это нарушение, которое всплывёт ровно тогда, когда у проекта появятся
деньги.

Вторая — техническая, и она непреодолима. Сцена уровня UE5 — это Nanite-меши на
миллионы треугольников, виртуальные текстуры и Lumen: рассчитано на 200 ГБ на
диске и дискретную видеокарту с потоковой подгрузкой. Пути импорта в браузер не
существует; «взять готовое» здесь означает переавторить всё заново.

Поэтому павильон собран из примитивов, но одет в настоящие материалы:
фотограмметрические сканы с ambientCG (полированный бетон, штукатурка, мрамор,
дерево) и освещение по фотографическому HDRI с Poly Haven. Всё под CC0 —
общественное достояние, без атрибуции и без ограничений на коммерческое
использование. Геометрия зала — несколько сотен треугольников вместо сотен
тысяч, материалы общие для всех павильонов, поэтому видеопамять тратится один
раз на весь мир.

Ассеты не коммитятся: `make world-assets` скачивает их по манифесту в
`apps/tools/src/fetch-assets.ts`, а `apps/web/public/world/LICENSES.md`
генерируется рядом и фиксирует источник и лицензию каждого файла.

### 4K-текстуры товаров

Библиотека материалов для товаров генерируется процедурно
(`apps/tools/src/gen-textures.ts`): пять материалов, по три карты 4096×4096 —
базовый цвет, нормали и ORM (occlusion в R, roughness в G, metalness в B).
Процедурная генерация выбрана вместо стоков сознательно: воспроизводимо,
детерминировано по сиду, без лицензионного следа.

Карты нормалей отдаются в JPEG, а не PNG, и это измерено: при качестве 96 без
субдискретизации цветности карта 4K падает с 22 МБ до 6 МБ, и при сравнении
один к одному разницы не видно. Без этого текстурированная модель не влезала бы
в лимит загрузки 50 МБ.

### Уровни качества

`apps/web/src/scene/quality.ts` — чистая функция от того, в чём браузер
признался: WebGL2, число ядер, память, максимальный размер текстуры, тип
указателя, строка рендерера. Четыре пресета: ultra, high, medium, low. Они
управляют разрешением текстур, тенями, постобработкой, пиксельным
соотношением, анизотропией, стартовым уровнем детализации и бюджетом видимых
товаров.

Функция намеренно ошибается вниз. Браузеры или врут о железе, или молчат;
машина, которая могла бы потянуть больше, отрисует на уровень ниже — этого никто
не заметит, а телефон, который не тянет, будет заикаться — это заметят все.
Программный растеризатор (SwiftShader) распознаётся отдельно: он рапортует
шестнадцать ядер и рисует пять кадров в секунду.

В рантайме есть две страховки: `AdaptiveDpr` снижает разрешение во время
движения и восстанавливает его за кадр, а `PerformanceMonitor` роняет целый
уровень, если частота кадров держится низкой. Только вниз — прыжки между
уровнями выглядят хуже, чем стабильно низкий.

Ниже нижнего уровня трёхмерного режима нет вовсе: плоский каталог берёт своё, и
покупка работает. Это не деградация, а гарантия.

### Что не должно ходить в чужие CDN

Три библиотечных умолчания пришлось отключить, и каждое стоило отдельного
разбора, потому что все три ломаются одинаково — тихо и внутри Suspense:

- `useGLTF` из drei скачивает декодер Draco с `gstatic.com`;
- `Environment preset` тянет HDRI из публичного бакета pmndrs;
- `Text` (troika) грузит индекс юникод-шрифтов с `jsdelivr`.

Любая из трёх означает, что сцена не работает без интернета и блокируется CSP
десктопной оболочки. Декодеры Draco и Basis копируются из установленного пакета
`three` (`apps/web/scripts/copy-decoders.mjs`), HDRI и шрифт лежат в манифесте
ассетов, освещение вьювера собрано в сцене из `Lightformer`.

### Стриминг и уровни детализации

Модель товара не запрашивается, пока покупатель дальше 22 метров, и
выгружается после 28 — разрыв в шесть метров, чтобы стоящий на границе человек
не дёргал загрузчик. Уровень детализации выбирается по расстоянию (6 и 13
метров), но не выше стартового уровня, заданного качеством: на телефоне мир
начинается со второго LOD и никогда не поднимается до нулевого.

Работа с расстоянием идёт в кадровом цикле, а не в состоянии React:
перерисовка происходит только при пересечении порога.

## Ограничение частоты запросов

Глобально 300 запросов в минуту на IP, на `/api/auth/register` и
`/api/auth/login` — 10 запросов за пять минут. Лимит на вход оказался первым,
во что упёрлись сквозные тесты: они теперь логинятся один раз и переиспользуют
сессию через `storageState`, а не обходят ограничение. За обратным прокси `trustProxy`
включается только в проде; ключ лимита должен считаться по проброшенному адресу,
иначе весь трафик схлопнется в один ключ.

## WebKit (этап 6)

Safari и WKWebView ведут себя иначе, чем Chrome, и это придётся чинить точечно:

- выбор формата сжатых текстур: на Apple GPU доступен ASTC, а не BC — KTX2 нужно
  собирать с обоими наборами;
- `SharedArrayBuffer` требует COOP/COEP-заголовков, иначе многопоточный декодер
  Draco молча падает в однопоточный режим;
- цветовое пространство и тонмаппинг в WebKit отличаются, сцена выглядит светлее;
- потеря контекста WebGL при сворачивании окна происходит чаще, нужен обработчик
  восстановления.
