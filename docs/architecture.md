# Архитектура 3DSFERA

Документ описывает принятые решения и причины, по которым они приняты. Он
обновляется в конце каждого этапа.

## Общая картина

```
                 ┌───────────────────────────────┐
   браузер /     │  apps/web                     │
   Tauri-окно ──▶│  React 19 + R3F (этап 3)      │
                 │  Zustand, Tailwind, i18next   │
                 └───────────────┬───────────────┘
                                 │ fetch, credentials: include
                                 │ httpOnly-кука sfera_sid
                 ┌───────────────▼───────────────┐
                 │  apps/api                     │
                 │  Fastify 5, zod, argon2       │
                 │  modules/*/service.ts —       │
                 │  бизнес-логика без HTTP       │
                 └───┬──────────────────┬────────┘
                     │ Prisma 7         │ S3 SDK
             ┌───────▼──────┐   ┌───────▼────────┐
             │ PostgreSQL   │   │ MinIO / S3     │
             │ 16           │   │ GLB, KTX2,     │
             │              │   │ превью         │
             └──────────────┘   └────────────────┘
```

`packages/shared` лежит поперёк: zod-схемы, DTO, коды ошибок и словари ru/en
собираются один раз и используются обеими сторонами. Схема, по которой сервер
валидирует запрос, — ровно тот же объект, которым форма подсвечивает поля.

## Решения и причины

### Монорепо на pnpm-воркспейсах, без Turborepo

Три приложения и один общий пакет. Turborepo окупается на десятках пакетов, а
здесь добавил бы ещё один конфиг и ещё один кэш. `pnpm --filter` покрывает всё,
что нужно.

### Бизнес-логика отдельно от транспорта

`src/modules/auth/service.ts` принимает хэндл базы и обычные значения, возвращает
обычные значения и бросает `AppError`. Он ничего не знает про Fastify, куки и
статус-коды — поэтому его тесты не поднимают сервер. Роут переводит результат в
HTTP. То же на фронте: `src/features/*/model.ts` — чистые функции, компоненты
только рендерят.

### Сессии в базе, а не JWT

Кука несёт случайный токен на 256 бит, в базе лежит его SHA-256. Из этого следуют
два свойства, которых у JWT нет без дополнительной инфраструктуры: сессию можно
отозвать мгновенно (блокировка поставщика выкидывает его из всех вкладок), а
дамп таблицы `sessions` нельзя переиграть как логин. Цена — один запрос к базе на
проверку; он идёт по уникальному индексу и стоит меньше, чем проверка подписи с
обращением к списку отзыва.

`lastSeenAt` обновляется не чаще раза в час — иначе каждый GET превращался бы в
запись.

### Пароли: argon2id

19 МиБ памяти, два прохода, параллелизм 1 — середина рекомендации OWASP. Логин
несуществующего пользователя всё равно прогоняет хэширование, чтобы отсутствие
аккаунта нельзя было определить по времени ответа.

### Защита от CSRF: SameSite=Lax плюс проверка Origin

Кука `sfera_sid` — `httpOnly`, `SameSite=Lax`, `Secure` в проде. Lax уже
отсекает межсайтовые POST-формы. Хук в `plugins/security.ts` дополнительно
отклоняет мутирующие запросы с чужим `Origin`. Запросы вообще без `Origin`
(curl, сервер-сервер) проходят: браузер без этого заголовка кук не пришлёт.

### Контракт ошибок: код, а не предложение

API отдаёт `{ error: { code: 'ERR_EMAIL_TAKEN', message, params?, issues? } }`.
`message` — английская строка для логов и curl, пользователю она не показывается
никогда. Текст собирает клиент из своего словаря. Без этого язык интерфейса и
язык писем разъезжаются в первый же месяц.

`issues` адресуют поле точечным путём (`address.postalCode`), форма подсвечивает
именно его.

### i18n с первого этапа

Словари живут в `packages/shared/src/i18n`. Тип словаря выводится из русского
файла, английский типизирован против него: забытый ключ — ошибка компиляции, а
не сырой ключ в интерфейсе. Тест `dictionaries` дополнительно сверяет наборы
ключей. Язык гостя берётся из localStorage, затем из браузера; у залогиненного
пользователя он хранится в аккаунте и переезжает между устройствами.

### Деньги и размеры — целые числа

Цены в минорных единицах (копейки), вес в граммах, габариты в миллиметрах. Float
для денег не используется нигде, включая расчёт доставки.

### Персональные данные

`ShippingAddress` — отдельная таблица, связанная с заказом один к одному. Ни имя,
ни телефон, ни адрес не денормализуются в `Order`, поэтому ограничение доступа
делается в одном месте. В `AuditLog` не пишутся ни адреса, ни email: только id
сущностей, действие и хэш IP с секретом (`hashIp`), который нельзя обратить
радужной таблицей.

### Prisma 7 и драйверные адаптеры

В седьмой версии строка подключения ушла из `schema.prisma`: миграции читают её
из `prisma.config.ts`, клиент получает через `@prisma/adapter-pg`. Клиент
генерируется в `apps/api/src/generated/prisma` и в гит не коммитится —
`postinstall` вызывает `prisma generate`.

### Файлы пользователей

Всё, что загрузил поставщик, лежит в S3-совместимом хранилище. Публичный префикс
`public/` (оптимизированные GLB, превью) отдаётся анонимно, оригиналы —
только по presigned-ссылкам с коротким сроком. Проверка формата — по содержимому
файла (magic bytes `glTF`), не по расширению; это будет реализовано на втором
этапе вместе с загрузкой.

В проде статику пользователей нужно отдавать с отдельного домена с жёсткими
`Content-Type` и `Content-Disposition` — иначе загруженный HTML исполнится в
контексте приложения.

## Ограничение частоты запросов

Глобально 300 запросов в минуту на IP, на `/api/auth/register` и
`/api/auth/login` — 10 запросов за пять минут. За обратным прокси `trustProxy`
включается только в проде; ключ лимита должен считаться по проброшенному адресу,
иначе весь трафик схлопнется в один ключ.

## WebKit (этап 6)

Safari и WKWebView ведут себя иначе, чем Chrome, и это придётся чинить точечно:

- выбор формата сжатых текстур: на Apple GPU доступен ASTC, а не BC — KTX2 нужно
  собирать с обоими наборами;
- `SharedArrayBuffer` требует COOP/COEP-заголовков, иначе многопоточный декодер
  Draco молча падает в однопоточный режим;
- цветовое пространство и тонмаппинг в WebKit отличаются, сцена выглядит светлее;
- потеря контекста WebGL при сворачивании окна происходит чаще, нужен обработчик
  восстановления.
